# 6. Technical Architecture (서비스 아키텍처)

> 宮今은 학기 중에는 비용과 운영 부담을 최소화한 **구현 아키텍처**로 개발·시연하고, 서비스가 확장되면 같은 코드를 그대로 옮겨 **목표 운영 아키텍처**로 전환합니다. 두 아키텍처는 모두 AWS 서울 리전(ap-northeast-2)을 기준으로 합니다.
>
> **v0.2 (2026-10-26) 변경:** 통합 기능명세서 v0.2 · API 명세서 v0.2 · ERD v0.2 · STT 벤치마크 결과 보고서 v2 · 백엔드 구현(gunggeum-be)을 반영했습니다. 질의응답 LLM이 Bedrock(Claude)에서 **OpenAI GPT-6 Luna**로, 실시간 음성 인식이 Amazon Transcribe에서 **Whisper large-v3-turbo + 위치별 사전**(학기 중 집 서버, 운영 시 EC2 GPU)으로 바뀌었고, 지원 언어는 **영어·태국어**로 정해졌습니다.

## 6.1 설계 원칙

**1. 무거운 처리는 기기와 CDN에서**
관광객 기능의 대부분은 서버가 필요 없습니다. 지도(PMTiles), 길찾기(다익스트라, `route.mjs`), 방문 판정(`judge.mjs`), 카메라 전각 인식(온디바이스 추론), 방문 여권은 모두 브라우저에서 처리하고, 위치는 서버로 보내지 않습니다. 필요한 파일(지도 타일, 판정 존, 인식 모델, 해설 오디오, 사진)은 S3에 올리고 CloudFront로 배포합니다.

**2. 서버는 실시간 통역과 질의응답만**
서버가 직접 처리하는 것은 실시간 통역(F8)과 RAG 질의응답·코스 추천(F5·F2), 그리고 이를 돕는 세션·공지·집계 API입니다. 부하 성격이 달라 `API 서비스`(REST)와 `실시간 통역`(WebSocket) 두 컨테이너로 분리합니다.

**3. 정확도가 검증된 엔진을 고르고, 가능한 것은 관리형으로** **[변경]**
- **실시간 음성 인식:** STT 벤치마크 v2(경복궁 해설 녹음 180발화)에서 전각명 인식률이 가장 높고 빠른 **Whisper large-v3-turbo + 위치별 받아쓰기 사전**(전각명 99.2%, 발화당 0.28초)을 씁니다. 같은 조건에서 Amazon Transcribe는 96.2%(어휘 + 후처리 사전), 사전 없이는 56.4%였습니다.
- **질의응답:** OpenAI GPT-6 Luna (질문 1건 약 1.4원 실측), 임베딩은 Amazon Bedrock Titan.
- **번역:** Amazon Translate (Custom Terminology로 표기 고정).

**4. 용어집을 모든 단계에 같은 표기로** **[변경]**
경복궁 고유명사 용어집(전각 354문단 · 용어 231개)을 음성 인식(위치별 받아쓰기 사전), 번역(Translate Custom Terminology), RAG 검색, 카드 링크(`[이름](card:id)`)에 공통으로 씁니다. 전각·용어 이름은 영어·태국어 모두 `음역 (짧은 뜻)` 한 형식입니다. 요구사항 N5(용어 일관성)를 데이터 구조로 충족합니다.

**5. 익명·무저장**
관광객은 회원가입 없이 접속합니다(N2). 해설사 음성은 STT 서버가 메모리에서 처리하고 버리며, 자막 원문도 서버와 DB에 저장하지 않습니다(놓친 자막은 순번으로만 알림). 서버에는 세션 집계값과 언급된 카드 id만 남습니다.

## 6.2 목표 운영 아키텍처

!architecture-target-v0.2.png

구독 가이드 86곳, 관광객 월 약 2.8만 명(9.3.3의 3년차)을 기준으로 한 운영 구성입니다. 기관 위탁 운영(B2G)에 필요한 가용성과 보안을 갖춥니다. **[제안]** 표시는 팀 결정 전입니다.

### 구성 요소별 설계 이유

**CloudFront + S3 (정적 파일)**

- 관광객 기능 대부분을 서버 없이 처리하므로, 관광객이 몰려도 서버가 아닌 CDN이 부하를 받습니다.
- CloudFront는 매월 1TB까지 무료이며, 3년차 예상 전송량(월 약 840GB)도 이 범위 안입니다.
- **WAF**로 질의응답·코스(LLM)와 세션 생성 요청 속도를 제한합니다. 가입 없는 익명 서비스라 봇 하나가 LLM·통역 비용을 크게 늘릴 수 있기 때문입니다.

**ECS Fargate (API 서비스 · 실시간 통역)**

- EC2와 달리 OS 패치, 인스턴스 교체를 직접 관리할 필요가 없어 백엔드 인력이 적은 팀에 적합합니다.
- 두 서비스는 부하 성격이 다릅니다. API 서비스는 관광객 수에, 실시간 통역은 동시에 진행되는 해설 세션 수에 비례합니다. 분리해 두면 해설 세션이 몰려도 질의응답이 느려지지 않고, 각자 필요한 만큼만 늘릴 수 있습니다.
- ARM(Graviton) 기반으로 같은 성능에서 약 20% 저렴합니다.

**STT 서비스 (EC2 GPU · Whisper turbo) [제안] [추가]**

- 학기 중 집 서버(1안)와 같은 모델·위치별 사전을 g4dn.xlarge(T4 GPU)에서 돌립니다. 가용 영역마다 1대, 궁 운영 시간(하루 10시간)에만 켭니다.
- 3년차 통역 월 2,580시간 기준으로 GPU 운영(약 58만 + 예비 11만)이 Transcribe 전부(약 217만)나 CLOVA Speech 전부(약 310만)보다 싸고, 벤치마크 정확도도 가장 높습니다.
- STT 서비스 장애·처리량 초과 시에는 Amazon Transcribe(위치별 사용자 지정 어휘 + 후처리 사전)로 넘깁니다.

**ElastiCache (Redis Pub/Sub)**

- 실시간 통역 서버가 2대 이상이면, 해설사가 연결된 서버와 관광객이 연결된 서버가 다를 수 있습니다.
- 자막을 Redis에 올리면 모든 서버가 받아 자기에게 연결된 관광객에게 전달합니다. 세션 진행 상태(마이크, 참여자 수, 해설사 위치)도 여기에 둡니다.

**RDS PostgreSQL (PostGIS · pgvector)**

- 한 DB에서 공식 자료 벡터 검색(pgvector, Titan 1024차원), 운영 데이터(세션 · 일정 · 공지 · 집계)를 모두 처리합니다.
- 경복궁 자료는 585건 규모라 별도 벡터 DB 없이 pgvector로 충분합니다 (검색 0.01초 미만, 2주차 보고서).
- Multi-AZ로 한 가용 영역이 멈춰도 DB가 유지됩니다.

**가용 영역 2개 · Private subnet · NAT Gateway**

- 가용 영역 2개로 한 데이터센터 장애에도 서비스가 유지됩니다.
- 서버와 DB는 Private subnet에 두어 인터넷에서 직접 접근할 수 없고, ALB를 통해서만 요청을 받습니다 (ALB는 WebSocket 지원).
- 서버가 OpenAI · AI 서비스 · 국가유산청 API에 접근할 때는 NAT Gateway를 거칩니다.

**AI · 외부 API** **[변경]**

- **OpenAI GPT-6 Luna:** 질의응답의 의도 분류 · 근거 문서 고르기 · 답변, 코스 설계(LLM 2회). 2주차 평가(60문항)에서 질문당 평균 4.3~5.9초, 약 1.4원. 외부 API라 **키는 Secrets Manager**에 두고 컨테이너에 주입합니다.
- **Bedrock Titan v2:** 문서·질문 임베딩(1024차원). IAM 역할로 호출합니다.
- **Translate:** Custom Terminology(추가 요금 없음)로 전각명 번역 표기를 고정합니다. 응답이 약 0.2~0.4초로 빨라 N4(3초 이내)를 맞추기 쉽고, 영어·태국어를 지원합니다.
- **Transcribe:** 대안 경로(STT 서비스 장애·초과분). 서울 스트리밍 초당 $0.0001667(분당 약 14원), 1초 단위, 최소 요금 없음.

**EventBridge + Lambda · EC2 GPU (필요할 때만)**

- 국가유산청 데이터 적재(주 1회)와 공지 수집(10분 간격)은 가끔만 실행되므로 상시 서버 대신 Lambda를 사용합니다.
- TTS 합성과 인식 모델 재학습은 원고·데이터가 바뀔 때만 GPU를 켜고, 결과물은 S3에 올린 뒤 끕니다.

## 6.3 학기 중 구현 아키텍처

!architecture-v0.2.png

학기 중(2026년 10월 ~ 12월 18일 최종발표)에 실제로 개발·배포·시연하는 구성입니다. **EC2 한 대 + CloudFront**를 중심으로, 지원금 안에서 운영하는 것을 목표로 합니다. 백엔드는 이 구성대로 구현되어 있습니다 (gunggeum-be, 테스트 55개).

### 구성 요소

| 영역 | 구성 | 역할 |
| --- | --- | --- |
| 진입 | CloudFront | HTTPS 제공, 정적 파일은 S3로, `/api`·`/ws` 요청은 EC2로 전달 |
| 정적 파일 | S3 | PWA, 지도(`servermap/`), 판정 데이터(`visit/`), 사진, 인식 모델, 해설 오디오, DB 백업 |
| 서버 | EC2 t4g.medium 1대 (Docker Compose) | 아래 5개 컨테이너 실행 |
| 컨테이너 | Nginx | 경로별 라우팅, IP별 요청 속도 제한 (질문·코스 분당 10회, 세션 생성 5회, 집계 30회), 에러 형식 통일 |
| 컨테이너 | API 서비스 (FastAPI) | 질의응답 · 카드 · 코스 · 세션 · 해설 일정 · 공지 · 방문 집계 (REST 11개) |
| 컨테이너 | 실시간 통역 (FastAPI WebSocket) | 해설사·관람객 소켓, 위치별 STT 사전, 번역, 카드 링크, 자막 전송 |
| 컨테이너 | PostgreSQL + pgvector | 공식 자료 585건 + 임베딩, 운영 테이블 7개 (세션·일정·공지·집계) |
| 컨테이너 | Redis | 자막 Pub/Sub, 세션 진행 상태 (디스크에 저장하지 않음) |
| 외부 API | OpenAI GPT-6 Luna · Bedrock Titan · Translate | RAG 답변·코스, 임베딩, 다국어 자막 |
| **집 장비 [추가]** | 1안 Z6 G4 (RTX 2070) · 3안 Mac mini (M1) | Whisper turbo 음성 인식 (stt-server). EC2와 사설 터널로 연결, 1안 실패 시 3안 |
| 외부 | 외부 GPU (Colab · Kaggle · 학교) | 전각 인식 모델 학습, TTS 음성 합성 → 결과만 S3에 업로드 |
| 배포 | GitHub Actions | 테스트, PWA는 S3에 업로드, 서버는 SSH로 배포 |
| 운영 | CloudWatch · AWS Budgets · IAM | 모니터링, 비용 알림($20·$40), 팀원별 계정·MFA |

### 목표 운영 아키텍처에서 줄인 부분과 이유

| 목표 운영 구성 | 학기 중 구현 | 줄인 이유 |
| --- | --- | --- |
| Route 53 + 도메인 + ACM | CloudFront 기본 주소 | 기본 주소(`xxxx.cloudfront.net`)가 이미 HTTPS를 제공 |
| 가용 영역 2개, Private subnet | 가용 영역 1개, Public subnet | 시연 기간 중 데이터센터 장애 가능성은 낮음 |
| ALB + NAT Gateway | 없음 | CloudFront가 EC2로 직접 연결, NAT만 월 약 12만원 |
| ECS Fargate | EC2 + Docker Compose | 서버 1대로 충분하고 팀원 모두 이해하기 쉬움 |
| RDS · ElastiCache | 같은 EC2 안의 컨테이너 | 시연 데이터는 매일 백업으로 충분 |
| WAF | Nginx 요청 속도 제한 | 같은 목적을 추가 비용 없이 구현 |
| **STT 서비스 (EC2 GPU)** | **집 장비 (Z6 G4 · Mac mini)** | 이미 있는 장비로 벤치마크 1안 그대로. AWS GPU는 학기 중 사용량에 비해 비쌈 |
| Secrets Manager | 서버의 `.env` 파일 (git 제외) | 키 몇 개라 파일로 충분 |
| EventBridge + Lambda | 운영자 명령(`app.cli`) · AI 배치 | 공지 수집 대상 미정, 문서는 AI 배치로 적재 |
| EC2 GPU (학습·TTS) | 외부 GPU | 가끔 쓰는 작업에 AWS GPU는 비쌈 |

## 6.4 실시간 통역 처리 흐름

두 아키텍처 모두 같은 흐름으로 동작합니다. 그림의 빨간 선이 이 경로입니다. **[변경]**

| 단계 | 처리 위치 | 내용 | 예상 소요 |
| --- | --- | --- | --- |
| 1 | 해설사 기기 | 음성 구간 검출(VAD)로 발화 하나를 잘라 WebSocket 프레임 1개로 전송 (WebM/Opus 7.6초 ≈ 23KB). 판정 존이 바뀌면 현재 위치도 전송 | 발화 끝 + 업로드 |
| 2 | 실시간 통역 서버 | 해설사 위치의 위치별 사전으로 받아쓰기 힌트 생성 (예: "경복궁 해설입니다. 흥례문, 영제교.") | 0초 |
| 3 | STT 서버 | Whisper large-v3-turbo 받아쓰기 (1안 실패 시 3안) | 0.28초 (Z6 G4) / 1.61초 (Mac mini) |
| 4 | 실시간 통역 서버 | (Transcribe 대안일 때만) 후처리 사전으로 고유명사 교정 | 0.5ms |
| 5 | Translate | 참여 언어별 병렬 번역, 용어집 표기 고정 | 약 0.2~0.4초 |
| 6 | Redis → WebSocket | 세션·언어별 자막 + 카드 링크 전송, 원문 병기. 해설사에게 인식 문장 미리보기 | 약 0.1초 |

- **발화가 끝난 뒤 약 1초 안**에 자막이 나오는 구성입니다 (Z6 G4 기준, 업로드 포함 추정). 이 맥(Apple Silicon, mlx)에서 실제 한국어 음성 4.5초 → 자막까지 2.03초를 쟀습니다 (번역 제외). 두 경우 모두 N4(3초 이내)를 만족합니다.
- 발화 단위로 받아쓰므로, 자막은 해설사가 한 문장을 끝낸 뒤 나옵니다 (말하는 도중 나오지 않음).
- **위치별 사전 효과 (같은 측정):** 사전 없이 `흥예문`·`영재교` → 사전 넣고 `흥례문`·`영제교`.
- **번역은 참여자 수가 아니라 참여 언어 수만큼 호출합니다.** 영어 관광객이 20명이어도 번역은 1회입니다.
- 놓친 자막은 다시 보내지 않고, 재연결한 관광객에게 놓친 순번(`gap`)만 알립니다. 자막 원문을 서버에 남기지 않기 위해서입니다.

## 6.5 서버 비용 **[변경]**

> 단가: AWS 공식 가격(서울 리전), 질의응답은 2주차 보고서 실측(GPT-6 Luna 질문 1건 약 1.4원), 음성 인식 비교는 STT 벤치마크 v2. 환율 1달러 = 1,400원. 가이드·관광객 수와 매출은 9.3.3 그대로.

### 주요 단가

| 항목 | 단가 | 근거 |
| --- | --- | --- |
| 질문 1건 (GPT-6 Luna + Titan) | 약 2원 | 실측 1.4원 (입력 약 9,400 · 출력 약 120토큰) + 의도 분류 여유 |

## 6.6 구현 아키텍처에서 목표 아키텍처로의 전환

처음부터 서비스 단위 컨테이너(`API 서비스`, `실시간 통역`)로 나누고 DB·Redis·STT 주소를 환경 변수로 받도록 개발했으므로, 전환 시 코드 변경은 거의 없습니다.

| 학기 중 구현 | 목표 운영 | 전환 시점 |
| --- | --- | --- |
| API 서비스 · 실시간 통역 컨테이너 | ECS Fargate 서비스 2개 | 트래픽이 서버 한 대를 넘을 때 |
| PostgreSQL 컨테이너 | RDS PostgreSQL Multi-AZ | 기관 위탁 운영(B2G) 계약 시 |
| Redis 컨테이너 | ElastiCache (Redis) | 실시간 통역 서버가 2대 이상이 될 때 |
| Nginx (요청 속도 제한) | ALB + WAF | Fargate 전환 시 함께 |
| **집 장비 STT (stt-server)** | **EC2 GPU STT 서비스 [제안]** | B2G 운영 시작 시 (같은 이미지·위치별 사전) |
| `.env` 파일 | Secrets Manager | Fargate 전환 시 함께 |
| 운영자 명령 · AI 배치 | EventBridge + Lambda | 공지 수집 대상이 정해질 때 |
| 외부 GPU | EC2 GPU (필요 시 기동) | 모델 재학습이 정기화될 때 |
| CloudFront 기본 주소 | Route 53 + ACM 도메인 | 정식 서비스 출시 시 |

- 컨테이너는 이미지 그대로 Fargate로 옮깁니다.
- PostgreSQL 데이터는 `pg_dump`로 내보내 RDS에 복원합니다.
- Redis·STT 서버 주소만 바꾸면 Pub/Sub·STT 호출 코드는 그대로 동작합니다 (`REDIS_URL`, `STT_HTTP_URLS`).

## 6.7 운영 안전장치와 검증 항목

### 안전장치

- **비용 알림:** AWS Budgets로 월 $20, $40 도달 시 이메일 알림을 받습니다.
- **계정 보안:** 팀 계정은 하나만 사용하고 루트 계정에 MFA를 적용합니다. 팀원은 각자 IAM 사용자로 접속하며, 액세스 키·OpenAI 키는 GitHub에 올리지 않습니다 (`.env`는 git 제외).
- **공개 QR 대비:** Nginx에서 IP별 요청 속도를 제한합니다 (질문·코스 분당 10회, 세션 생성 5회). 해설 세션 생성은 가이드 접근 코드(`GUIDE_ACCESS_CODE`)가 있어야 합니다.
- **데이터 백업:** 매일 PostgreSQL 백업(`pg_dump`)을 S3에 저장합니다.
- **시연 대비:** 서버가 한 대이므로 현장 테스트와 최종발표 전날 EC2 스냅샷(AMI)을 만들어, 장애 시 몇 분 안에 같은 서버를 다시 띄웁니다. 집 장비가 멈추면 Mac mini(3안), 둘 다 멈추면 Transcribe(2 대안)로 바꿔 띄울 수 있게 미리 한 번씩 리허설합니다.
- **종료 정리:** 최종발표(12/18) 이후 EC2, EBS, 고정 IP, S3를 삭제합니다. 고정 IP는 인스턴스를 꺼도 과금됩니다.
